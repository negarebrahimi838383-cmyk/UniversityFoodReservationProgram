 # طراحی پایگاه داده – 

این سند توضیح می‌دهد که سامانه رزرو غذا چه اطلاعاتی را چگونه در پایگاه داده ذخیره می‌کند.

---

# 1) جدول کاربران (Users)
این جدول اطلاعات دانشجویان و مدیر را نگه می‌دارد.

### ستون‌ها:
- **id** (شناسه کاربر)
- **name** (نام)
- **email** (ایمیل)
- **student_id** (شماره دانشجویی)
- **role** (نقش کاربر: student یا admin)
- **created_at** (زمان ثبت نام)

---

# 2) جدول غذاها (Meals)
این جدول غذاهای هر روز را ذخیره می‌کند.

### ستون‌ها:
- **id** (شناسه غذا)
- **date** (تاریخ ارائه غذا)
- **meal_type** (صبحانه/ناهار/شام)
- **name** (نام غذا)
- **description** (توضیح غذا)
- **capacity** (ظرفیت غذای قابل ارائه)
- **price** (قیمت)
- **created_at** (زمان ایجاد)

---

# 3) جدول رزروها (Reservations)
هر بار که دانشجو یک غذا رزرو می‌کند، یک رکورد اینجا ثبت می‌شود.

### ستون‌ها:
- **id** (شناسه رزرو)
- **user_id** → وصل به جدول Users  
- **meal_id** → وصل به جدول Meals  
- **quantity** (تعداد)
- **status** (وضعیت: confirmed / cancelled)
- **created_at** (زمان ایجاد رزرو)

---

# 4) جدول وضعیت سفارش آشپزخانه (KitchenOrders)
این جدول وضعیت آماده‌سازی غذا توسط آشپزخانه را ذخیره می‌کند.

### ستون‌ها:
- **id**
- **reservation_id** (به رزرو وصل است)
- **status** (pending / preparing / ready / delivered)
- **updated_at**

---

# 5) روابط بین جدول‌ها
- هر **کاربر** می‌تواند چند **رزرو** داشته باشد.  
- هر **غذا** می‌تواند چند **رزرو** داشته باشد.  
- هر **رزرو** یک **وضعیت سفارش در آشپزخانه** دارد.
